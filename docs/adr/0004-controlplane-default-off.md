# ADR-0004: controlplane не входит в релиз по умолчанию

Дата: 2026-09-25. Статус: принят (в рамках T13).

## Контекст
`services/controlplane.py` — подписчик NATS-subject'ов `dashboard.apply.*` /
`dashboard.ops.*` и писатель heartbeat под **старую BFF-архитектуру**
(dashboard-mvp: BFF публиковал команды, controlplane применял). Новое web-API
(этот репозиторий, `api/bot.py`) выполняет те же действия **сам**, durable-операциями
через журнал (T08), — активного производителя сообщений на эти subject'ы больше нет.
В текущем проде контейнер `dsbot-controlplane` запущен «по наследству» из
dashboard-mvp compose и только пишет heartbeat.

Решение владельца (п.7 плана T13): до появления активного потребителя новой
архитектуры controlplane не включать автоматически; «контейнер Up» — не основание.

## Решение
- В production/staging compose (`deploy/*/compose*.yml`) сервис `controlplane`
  существует, но под compose-профилем `controlplane` — **вне профиля он не
  рендерится в `compose config --services` и не стартует никогда**
  (preflight/validate_compose.py проверяют наличие профиля; P02).
- Включение — только осознанным `docker compose --profile controlplane up -d
  controlplane` с записью в runbook, кто и зачем включил.
- Если активный потребитель появится, до включения обязаны быть задокументированы:
  - **issuer** (кто публикует apply/ops-сообщения) и **subject**-контракт с версией;
  - **producer**-сторона: обработка idempotency (повтор доставки не должен
    применять изменение дважды — через op-journal/T08-ключ), иначе включение
    запрещено;
  - тесты идемпотентности применения (сейчас их нет — добавить при активации);
  - Ожидаемое поведение: controlplane остаётся совместимым и не ломает существующий
    web-контракт.

## Последствия
- Сервис продолжает жить в репозитории и в CI-матрице образов (история не удаляется);
  heartbeat worker `dsbot-controlplane` при выключенном профиле не публикуется —
  healthcheck-CLI для него не применяется (алиас worker сохранён на будущее).
- Legacy BFF/UI/workers из dashboard-mvp в новые манифесты не мигрируют вообще:
  они часть старой инсталляции, её судьба — T18 cutover.
